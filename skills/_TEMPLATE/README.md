> what you have is an article, not a skill.

## 4. Build it

Numbered steps from an empty folder to a working thing. Every step should be verifiable on its own
— the reader should never go more than a few minutes without being able to check they are on track.

1. **Step name.** What to do, and what you should see when it worked.
2. **Step name.** ...

## 5. Checkpoint

The specific, objective test that decides whether you have this skill. Include the inputs, the
expected behaviour, and the failure cases it must survive.

- [ ] It does the main thing correctly on normal input
- [ ] It behaves sensibly on empty / huge / malformed input
- [ ] It fails loudly rather than silently when it cannot succeed
